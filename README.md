# Театральные часы (48 минут)

Минимальный сценический таймер `00:48:00 → 00:00:01`. Две страницы на GitHub Pages:

- `index.html` — огромные семисегментные часы для проектора;
- `control.html` — пульт оператора: старт, пауза, скорость 0.25×/0.5×/1×/1.5×/2×/4×, установка времени, сброс.

**Хостинг и собственный сервер не нужны:** GitHub Pages + Firebase Realtime Database на бесплатном тарифе Spark. База хранит только *опорное* время, дату его установки, скорость и флаг воспроизведения, а не обновляет счётчик каждую секунду.

## 1. Сначала можно открыть без Firebase

Запустите локальный статический сервер (не открывайте HTML файлы напрямую через `file://`):

```bash
cd theatre-clock
python3 -m http.server 8000
```

Откройте `http://localhost:8000/` и `http://localhost:8000/control.html` в двух вкладках **одного браузера**. По умолчанию включён ДЕМО-режим: изменения передаются через `localStorage`. ДЕМО не синхронизируется между разными устройствами и не подходит для выступления.

## 2. Настройка Firebase (для выступления обязательна)

1. Перейдите на [Firebase Console](https://console.firebase.google.com/) → **Add project**. Google Analytics можно отключить; план **Spark (бесплатный)**. Если сервис предлагает включить биллинг, этого делать **не нужно**.
2. В Project settings → General → **Your apps** нажмите Web (`</>`) → Register app. Скопируйте **firebaseConfig**.
3. Перейдите в **Build → Realtime Database** → Create database. Режим **Locked**, регион можно выбрать ближайший. После создания скопируйте точный `databaseURL` вида `https://....firebasedatabase.app` или `https://....firebaseio.com`.
4. **Уже готово:** публичные параметры веб-приложения `the-cherry-orchard` внесены в `js/config.js`. **Никогда не вставляйте приватный ключ Service Account или пароль пользователя в код.**
5. В **Build → Authentication → Sign-in method** активируйте **Email/Password**. Затем откройте вкладку **Users → Add user**, создайте отдельного оператора с сильным паролем. Скопируйте его **User UID**.
6. **Уже готово:** `database.rules.json` содержит UID оператора `s5Ss40x2ZjaukMDedkWlRr73LZj1`. Скопируйте весь JSON в **Realtime Database → Rules** и нажмите **Publish**. Правила дают всем только чтение `timer`, а изменять его может исключительно оператор с указанным UID.
7. Не используйте правила из тестового режима `.read: true, .write: true`.

## 3. Разместить на GitHub Pages

1. Создайте **публичный** репозиторий на GitHub (например, `theatre-clock`) и загрузите туда содержимое **этой папки**, чтобы `index.html` лежал в корне репозитория. Отдельный домен не нужен.
2. На GitHub: **Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save**.
3. После публикации ссылки обычно выглядят так:
   - `https://USERNAME.github.io/theatre-clock/` — часы;
   - `https://USERNAME.github.io/theatre-clock/control.html` — пульт.
4. Откройте страницу часов в браузере на ноутбуке/проекторе, а пульт на другом устройстве (можно через мобильный интернет). На пульте выполните вход, нажмите «Запустить» и проверьте синхронизацию.

### Важные замечания

- **Сеть:** при потере интернета уже загруженные часы продолжают отсчёт по последнему полученному состоянию. Новые команды с пульта без связи не отправляются, после восстановления подключения часы синхронизируются. Не закрывайте страницу часов.
- **Перезагрузка:** при повторном открытии страницы она получает последнее состояние и рассчитывает актуальное время. Если физические часы устройств существенно сбиты, возможен сдвиг; Firebase `.info/serverTimeOffset` компенсирует это в обычных условиях.
- **Оператор:** только один аккаунт с правом управления. Ссылку на `control.html` можно передавать, но без пароля и соответствующего UID команды не пройдут.
- **Минимальное время:** счётчик останавливается на `00:00:01`. Кнопка «Запустить» на этом значении ничего не делает; нажмите «Сбросить» или установите большее время.
- **Оформление:** экран часов белый, сегменты почти чёрные. На сценическом экране лучше отключить сон ноутбука/блокировку экрана и вручную включить полноэкранный режим.
- **Пароли не размещать** в коде или GitHub. Конфигурация Firebase и UID не являются секретами, а пароль должен оставаться у оператора.

## 4. Минимальная проверка перед спектаклем

- [ ] На пульте после входа «На связи»; нет баннера «ДЕМО».
- [ ] На двух **разных устройствах** один и тот же таймер.
- [ ] «Запустить» → после одной секунды `00:47:59`.
- [ ] «Пауза» → время не меняется несколько секунд.
- [ ] 2× на ходу → таймер идёт вдвое быстрее.
- [ ] 0.5× на ходу → таймер идёт вдвое медленнее.
- [ ] Установка `00:01:00` → запускаем и проверяем остановку на `00:00:01`.
- [ ] Перезагрузка браузера часов не сбрасывает отсчёт.
- [ ] При отключении интернета на экране часы продолжают идти.
- [ ] Сохранили оператору обе ссылки и логин; проверили проектор/запрет сна.
